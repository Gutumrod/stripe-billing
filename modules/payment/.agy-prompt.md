# MODULE 5 — Payment Core + Stripe Adapter

## Objective
Create a central payment abstraction:
```
Business Project
      ↓
Payment Core
      ↓
Payment Provider
      ↓
Stripe
```
Business Project MUST NOT call the Stripe SDK scattered across the system.

## Core Responsibilities
Support concepts: create payment, retrieve payment, refund, payment status, provider metadata.

## Payment Request
```ts
type CreatePaymentRequest = {
  amount: number
  currency: string
  referenceId: string
  customerId?: string
  description?: string
  metadata?: Record<string, string>
}
```

## Result
```ts
type PaymentResult = {
  success: boolean
  paymentId?: string
  status?: string
  checkoutUrl?: string
  provider?: string
  providerReference?: string
  error?: PaymentError
}
```

## Provider Contract
```ts
interface PaymentProvider {
  createPayment(...)
  getPayment(...)
  refundPayment(...)
}
```

## Stripe Adapter
v0.1 implement Stripe. Secrets injected from Host. NEVER hard-code Stripe secret.

## Amount Rule
Core must clearly define: use minor units. e.g. 10000 = 100.00 THB. NEVER use floating-point for money inside core.

## Payment State
Core normalized status: pending, requires_action, processing, succeeded, failed, refunded, cancelled.
Stripe-specific status MUST be mapped into normalized status.

## Idempotency
Every create/refund operation MUST support idempotencyKey.

## Webhook
Payment Module MUST NOT build new webhook infrastructure. Must use Webhook Receiver Module.
Stripe Adapter MAY have parsePaymentEvent(), but request verification is the Webhook Receiver/Stripe verifier's job.

## Security
NEVER: accept card number directly, store CVV, log payment secret, log sensitive payment method.
Use Stripe-hosted/tokenized flow per use case.

## Out of Scope
subscription, plan, entitlements, invoice UI, accounting, tax engine.

## Tests
Use provider mocks first. At minimum: create payment success, create failure, retrieve, refund, double request/idempotency, invalid amount, unsupported currency, provider timeout, error normalization.
Stripe integration test separate from unit test.
